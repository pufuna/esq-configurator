# Конфигураторы ESQ — внедрение на корпоративный портал «Элком»

Для ИТ-отдела и ответственного за конфигураторы. Сайт — внутренний инструмент менеджеров:
конфигураторы ВВ ПЧ ESQ F ME800 / ME800-R и ВВ УПП ESQ F HVS, ТКП в PDF и Word, реестр выданных ТКП,
разбор ТЗ, расчёт энергосбережения.

## 1. Что это технически

- **Статический сайт**: HTML, JavaScript, PDF, картинки, шрифты. Ни базы данных, ни PHP/.NET/Node на портале не нужно —
  подойдёт любой веб-сервер (IIS, nginx, Apache) и любая CMS, если в ней можно выложить папку с файлами как есть.
- **Объём** — около 210 МБ, ~510 файлов (в основном габаритные чертежи в PDF). Браузер скачивает их только по требованию:
  страница конфигуратора весит около 0,6 МБ.
- **ТКП собирается в браузере** сотрудника — сервер портала не нагружается.
- **Серверная часть — в Яндекс.Облаке** (Cloud Functions), отдельно от портала:

  | Функция | Что делает | Адрес |
  |---|---|---|
  | Основная (ТКП и разбор ТЗ) | пароль сотрудника для скачивания ТКП, распознавание ТЗ | `https://functions.yandexcloud.net/d4eplvhu1pvut5be24vd` |
  | Общий реестр ТКП | хранит записи о выданных ТКП, пароль для просмотра | `https://functions.yandexcloud.net/d4evqb70lqivk4dvvq4d` |

## 2. Содержимое архива

| Файл / папка | Назначение |
|---|---|
| `index.html` | главная: выбор конфигуратора |
| `configurator_vv_pch.html`, `vv_upp.html` | конфигураторы ПЧ и УПП |
| `registry.html` | реестр выданных ТКП |
| `tz.html` | разбор ТЗ (вход — по значку © в подвале конфигуратора) |
| `energy.html` | расчёт энергосбережения |
| `*.js` | логика страниц и генераторы ТКП |
| `assets/` | чертежи, документация, шаблоны ТКП, шрифты, библиотеки — **копировать целиком** |
| `web.config` | настройки для IIS (если сервер не IIS — можно удалить) |
| `.htaccess` | настройки для Apache (если сервер не Apache — можно удалить) |
| `nginx.conf.example` | пример настроек для nginx (на сайте не нужен — удалить после настройки) |

## 3. Размещение

1. Выберите адрес. Лучше всего — отдельная папка или поддомен, например `https://portal.elcom.ru/configurator/`
   или `https://configurator.elcom.ru/`. Все ссылки внутри сайта относительные: работает в любой папке.
2. Распакуйте архив в эту папку **со всей структурой** (`assets/…` — рядом с `index.html`).
   Имена файлов — в UTF-8, есть кириллица и пробелы (`assets/drawings/6KV 280 KW габаритный чертеж.pdf`):
   распаковывайте средствами, которые сохраняют имена (7-Zip, `unzip` в Linux, Проводник Windows 10+).
3. Настройте веб-сервер (раздел 4).
4. **Закройте доступ снаружи**: только внутренняя сеть / VPN или авторизация портала. Пароли внутри сайта
   защищают только скачивание ТКП и реестр, а сами страницы, чертежи и документация открыты всем, у кого есть адрес.
5. Если портал на **1С-Битрикс** или другой CMS: выложите папку как статические файлы (в корень сайта, мимо компонентов
   и шаблонов CMS). Встраивать страницы внутрь шаблона портала не нужно — в конфигураторе свои шапка и подвал
   и кнопка «На главную». Ссылку на конфигуратор достаточно добавить в меню портала.
   Встраивание в страницу портала через `<iframe>` возможно, но на телефоне неудобно (двойная прокрутка).

## 4. Настройки веб-сервера

**Обязательно:**

- **HTTPS.** Без него не работают проверка пароля сотрудника (хэширование в браузере) и копирование в буфер.
- **Типы файлов** (MIME). Если их нет, разбор ТЗ не читает PDF, а шрифты и картинки не загружаются:

  | Расширение | Тип |
  |---|---|
  | `.mjs` | `text/javascript` |
  | `.webp` | `image/webp` |
  | `.woff2` | `font/woff2` |
  | `.json` | `application/json` |

  - **IIS** — `web.config` из архива уже это делает (лежит рядом с `index.html`).
  - **Apache** — `.htaccess` из архива (нужен `AllowOverride FileInfo`; для заголовков кэша — модуль `mod_headers`).
  - **nginx** — см. `nginx.conf.example`; в старых версиях допишите `mjs` и `woff2` в `mime.types`.
- **Чертежи открываются во встроенном окне** на той же странице: заголовок `X-Frame-Options` — не строже `SAMEORIGIN`,
  в CSP (если есть) — `frame-src 'self'`.

**Если на портале задана политика безопасности (Content-Security-Policy)** — она должна разрешать:

```
default-src 'self'; script-src 'self' 'unsafe-inline' https://cdn.jsdelivr.net; style-src 'self' 'unsafe-inline';
img-src 'self' data: blob:; font-src 'self'; connect-src 'self' https://functions.yandexcloud.net https://cdn.jsdelivr.net;
worker-src 'self' blob:; frame-src 'self'; object-src 'none'; base-uri 'self'
```

С этой политикой сайт проверен целиком (nginx, Chromium). `https://cdn.jsdelivr.net` — необязательный запасной источник
библиотек: без него всё работает из `assets/vendor/`, только на странице разбора ТЗ первая загрузка PDF на секунду дольше.
`'unsafe-inline'` обязателен — скрипты встроены в страницы.

**Желательно — кэш.** Страницы и скрипты (`.html`, `.js`, `.mjs`, `.json`) — с заголовком `Cache-Control: no-cache`
(браузер хранит файл, но сверяет его с сервером): после обновления никто не останется со старой версией.
Чертежи, картинки и шрифты можно кэшировать надолго. В `web.config`, `.htaccess` и примере nginx это уже настроено.

**Сеть и прокси компании.** Браузеры сотрудников должны иметь доступ к `https://functions.yandexcloud.net`
(пароль ТКП, общий реестр, разбор ТЗ). Если исходящий интернет идёт через прокси с белым списком — добавьте этот адрес.

## 5. Облачные функции — что поменять при переезде

1. **Адрес сайта в функции реестра.** Консоль Yandex Cloud → Cloud Functions → функция реестра → «Редактор» →
   переменные окружения → `ALLOW_ORIGIN` = адрес портала **без пути и без слэша на конце**, например
   `https://portal.elcom.ru`. Если переменной нет — запросы разрешены с любого сайта, и это тоже работает;
   если она указывает на старый адрес (`https://pufuna.github.io`) — общий реестр на портале работать не будет.
2. **Новая версия функции реестра** — с защитой от подбора пароля и быстрым открытием реестра за всё время.
   Код — `cloud/registry/index.js` в репозитории. В той же функции: «Редактор» → заменить содержимое `index.js` →
   «Сохранить изменения». Остальные настройки (бакет, сервисный аккаунт, переменные) не меняются.
3. **Аккаунт Яндекс.Облака.** Функции и бакет с реестром сейчас живут в облаке, где их создали при разработке.
   Для корпоративного использования стоит перенести их в облако «Элкома» (оплата, доступы, ответственный) —
   по шагам `cloud/registry/README.md`; после переноса новые адреса функций вписываются в `registry.js` (реестр),
   `tz.js`, `configurator_vv_pch.html` и `vv_upp.html` (`FUNCTION_URL`). Это можно сделать и позже — сайт на портале
   работает с текущими функциями.

## 6. Пароли и защита от подбора

- Пароли **общие для всех сотрудников**: пароль ТКП (запрашивается, если составитель — сотрудник из списка)
  и пароль реестра (переменная `REGISTRY_PASSWORD` функции реестра). Когда сотрудник с доступом увольняется —
  поменяйте пароль в переменных функции и сообщите новый коллегам. Пароль — не короче 12 символов.
- **Защита от подбора (функция реестра):** 10 неверных паролей с одного адреса за 15 минут → адрес блокируется на 15 минут,
  при повторе — на 30 минут, час … до суток. Верный пароль сбрасывает счётчик. Порог выбран с запасом,
  потому что у офиса обычно **один внешний адрес на всех**: опечатки коллег складываются.
  Запись о скачанном ТКП работает и во время блокировки — менеджеры продолжают выдавать ТКП.
- **Снять блокировку вручную:** Object Storage → бакет реестра → папка `a/` → удалить файлы (это только счётчики,
  записи реестра лежат в `e/`, кэш — в `c/`).
- На страницах после каждого неверного пароля кнопка входа блокируется на 2, 4, 8 … 60 секунд.
- **Основная функция (пароль ТКП, разбор ТЗ)** — её код не хранится в этом репозитории. Чтобы и там была защита
  от подбора на сервере, перенесите в неё блок «защита от подбора пароля» из `cloud/registry/index.js`
  (функции `sourceIp`, `passwordOk`, `guard` и проверка в начале обработчика; нужен бакет — можно тот же,
  что у реестра). Пока этого не сделано, перебор ограничен только паузами на странице.

## 7. Переезд сотрудников с адреса на GitHub

- **Общий реестр** хранится в облаке — на портале он будет тот же, ничего переносить не нужно.
- **Данные, сохранённые в браузере** (заполненная форма, записи реестра «этого браузера», ещё не отправленные в общий),
  привязаны к адресу сайта и на новый адрес не переедут. Перед переходом каждому менеджеру: старый адрес →
  «Реестр выданных ТКП» → войти в общий реестр → «Отправить записи этого браузера в общий реестр».
  Либо выгрузить CSV и загрузить его на странице реестра на новом адресе.
- **Ссылки на конфигурации**, уже отправленные коллегам, ведут на старый адрес. После переезда на старом адресе
  можно поставить переадресацию на портал — сообщите новый адрес разработчику.

## 8. Проверка после установки (10 минут)

1. Открыть главную — логотипы, картинки, шрифт как на скриншотах; в подвале — текущий год.
2. Конфигуратор ПЧ → «Техническое описание» — внизу открывается габаритный чертёж (PDF во встроенном окне).
3. Заполнить «Составил» (например, «Иванов И.И.») → «Скачать ТКП (PDF)» и «Word» — оба файла скачиваются.
4. То же в конфигураторе УПП.
5. «Реестр выданных ТКП» → войти паролем реестра → только что скачанные ТКП в списке.
6. Разбор ТЗ (© в подвале) → войти → загрузить любое ТЗ в PDF — текст распознаётся.
7. В браузере F12 → «Консоль»: нет красных ошибок; «Сеть»: нет ответов 404.
   Частые причины проблем: 404 на `.mjs`/`.woff2`/`.webp` — не настроены типы файлов; ошибки «Content Security Policy» —
   см. раздел 4; ошибки запросов к `functions.yandexcloud.net` — прокси или `ALLOW_ORIGIN`.

## 9. Обновление сайта

Изменения конфигураторов ведутся в репозитории `pufuna/esq-configurator`. Новый архив собирается командой

```
python tools/build_portal.py
```

(Python 3, без доп. библиотек) → `dist/esq-configurator-<дата>.zip`. Обновление на портале:

1. Распаковать новый архив во временную папку рядом с рабочей.
2. Переименовать: рабочую → `configurator_old`, новую → `configurator` (так сайт ни секунды не будет «наполовину старым»).
3. Проверить по разделу 8, старую папку удалить.

Можно автоматизировать: GitHub Actions будет собирать архив и выкладывать его на сервер портала (по SFTP или SMB) после
каждого изменения — нужен технический доступ к серверу.
