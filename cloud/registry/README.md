# Общий реестр ТКП — облачная функция

Функция принимает записи о скачанных ТКП с сайта и хранит их в бакете Object Storage.
Сотрудники видят общий реестр на странице `registry.html` после ввода пароля.

Код — один файл `index.js`, сторонних библиотек нет.

## Развёртывание в консоли Yandex Cloud (≈15 минут)

Всё делается в том же каталоге облака, где уже работает ваша функция.

### 1. Бакет для записей

1. **Object Storage** → **Создать бакет**.
2. Имя — например `esq-tkp-registry` (имя должно быть уникальным во всём Yandex Cloud; если занято — допишите что-нибудь).
3. **Доступ на чтение объектов** — *Ограниченный*, **Доступ к списку объектов** — *Ограниченный*.
   Записи не должны быть видны снаружи: в них цены.
4. Максимальный размер — можно оставить по умолчанию. **Создать бакет**.

### 2. Сервисный аккаунт для функции

1. **Identity and Access Management** → **Сервисные аккаунты** → **Создать сервисный аккаунт**.
2. Имя — например `esq-registry`.
3. Роль — **`storage.editor`** (на каталог). **Создать**.

### 3. Функция

1. **Cloud Functions** → **Создать функцию**, имя — например `esq-tkp-registry` → **Создать**.
2. **Редактор** (создать версию): среда выполнения **Node.js 18** или новее, без примеров кода → **Продолжить**.
3. В редакторе: удалите пример, если он есть, создайте файл `index.js` и вставьте в него содержимое `cloud/registry/index.js` из репозитория.
4. Параметры версии:
   - **Точка входа** — `index.handler`
   - **Таймаут** — `30` секунд
   - **Память** — `256 МБ`
   - **Сервисный аккаунт** — `esq-registry` (из шага 2)
   - **Переменные окружения**:

     | Ключ | Значение |
     |---|---|
     | `BUCKET` | имя бакета из шага 1 |
     | `REGISTRY_PASSWORD` | пароль для просмотра реестра — только для допущенных сотрудников |
     | `ALLOW_ORIGIN` | адрес сайта, например `https://pufuna.github.io` — необязательно, без него запросы разрешены с любого сайта |

5. **Сохранить изменения** — создастся версия.
6. Вкладка **Обзор** → включите **Публичная функция** (иначе сайт не сможет её вызвать; пароль и проверка записей — внутри функции).
7. Скопируйте **Ссылку для вызова** — `https://functions.yandexcloud.net/…`.

### 4. Подключение сайта

В файле `registry.js` впишите ссылку из шага 3.7:

```js
const REGISTRY_FUNCTION_URL = 'https://functions.yandexcloud.net/…';
```

и опубликуйте сайт. (Или пришлите ссылку — впишу сам.)

### 5. Проверка

1. Скачайте любое ТКП в конфигураторе.
2. Откройте **Реестр выданных ТКП**, введите пароль из `REGISTRY_PASSWORD` — ТКП должно быть в списке.
3. Кнопка **«Отправить записи этого браузера в общий реестр»** переносит то, что каждый сотрудник накопил у себя до подключения. Повторная отправка не создаёт дублей.

## Как это устроено

- Одна запись — один объект `e/ГГГГ-ММ/<дата>_<id>.json` в бакете. Запись с тем же id перезаписывается — дублей не бывает.
- Добавлять записи может сайт без пароля (так же, как он скачивает ТКП). Смотреть, удалять и загружать пачкой — только с паролем.
- В запись попадают только поля реестра ограниченной длины — функция отбрасывает всё лишнее.
- Если связи с функцией нет, запись остаётся в браузере с пометкой «не отправлено» и уходит при следующем открытии сайта.
- Стоимость — в пределах бесплатных лимитов Cloud Functions и копейки за хранение в Object Storage.

## Проверка кода

`node tests/registry_function.test.js` — функция на локальном макете Object Storage (без облака).
`tests/run_tests.py` — сайт вместе с функцией в браузере.
